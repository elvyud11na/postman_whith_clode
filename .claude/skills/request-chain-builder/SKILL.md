# Генератор цепочек запросов

## Как работать

1. Определи шаги сценария и зависимости между ними:
   - Какой запрос идёт первым (обычно — авторизация/логин)
   - Что каждый шаг должен передать следующему (токен, id созданной сущности, статус)
   - Есть ли условные ветвления (например, если создание не удалось — не идти дальше)

2. Если сценарий не описан пользователем явно — уточни:
   - "какой первый шаг сценария?"
   - "что именно нужно передать дальше — токен, id, что-то ещё?"
   Не выдумывай бизнес-логику процесса (особенно для банковских/финансовых сценариев — уточняй, а не гадай).

3. Для каждого шага в цепочке:
   - Определи, какие данные нужно **сохранить** из ответа (через `pm.environment.set(...)` или `pm.collectionVariables.set(...)` в скрипте Tests текущего запроса)
   - Определи, где эти данные **используются** в следующем запросе (в URL, заголовках, теле — через `{{variable_name}}`)

4. Явно указывай, где именно вставлять код:
   - Сохранение переменной → вкладка **Tests** запроса-источника
   - Использование переменной → сам запрос (URL/Headers/Body), синтаксис `{{имя_переменной}}`

5. Если запросы уже существуют в Postman-коллекции (доступны через MCP) — предложи обновить их напрямую (добавить скрипт сохранения переменной, подставить плейсхолдер в следующий запрос), а не просто вывести инструкцию текстом.

6. В конце — кратко опиши порядок выполнения шагов (по какому пути двигаться в Postman Runner/Collection Runner), если шагов больше двух.

## Формат вывода (пример: логин → запрос с авторизацией)

### Шаг 1: POST /auth/login
Добавить в **Tests**:
```javascript
const jsonData = pm.response.json();
pm.environment.set("auth_token", jsonData.token);
```

### Шаг 2: GET /users/me
В **Headers** запроса:
```
Authorization: Bearer {{auth_token}}
```

**Порядок выполнения:** Login → Get Users Me (запусти оба через Collection Runner последовательно, либо вручную в этом порядке).

## Что НЕ делать

- Не придумывай названия переменных, отличные от контекста проекта без согласования — используй понятные имена (`auth_token`, не `x1`).
- Не строй сценарий длиннее, чем реально описал пользователь — не добавляй "на всякий случай" лишние шаги.
- Не путай `pm.environment.set` и `pm.collectionVariables.set` — уточни у пользователя, если неясно, какой тип переменных используется в его окружении.
