# Генератор чек-листа тестирования

## Как работать

1. Определи тип объекта: UI-фича, API-эндпоинт, или общий пользовательский сценарий.
2. Собери контекст: если пользователь дал описание требований/спеку — используй его; если нет — задай 1-2 уточняющих вопроса (например: "какой метод — GET/POST?", "есть ли авторизация?").
3. Построй чек-лист по разделам:
   - Позитивные сценарии
   - Негативные сценарии (невалидные данные, отсутствующие поля)
   - Граничные значения
   - Авторизация/права доступа (если применимо)
   - Производительность/нагрузка (только если явно просили)
4. Формат вывода — маркированный список с чекбоксами `- [ ]`, без лишних пояснений.

## Пример вывода

- [ ] Успешный запрос с валидными данными возвращает 200 и ожидаемую структуру ответа
- [ ] Запрос без обязательного поля X возвращает 400 с понятным сообщением об ошибке
- [ ] Запрос с истёкшим токеном возвращает 401
...
