# Diff между версиями API

## Как работать

1. Определи источники сравнения:
   - Две OpenAPI/Swagger-спеки (файлы или из workspace через MCP)
   - Два примера ответа одного эндпоинта (старый/новый)
   - Старая и новая версия коллекции Postman
   Если дан только один источник — попроси второй, не гадай, что могло измениться.

2. Сравнивай по слоям, в этом порядке:
   - **Эндпоинты**: какие добавлены, какие удалены, у каких изменился путь или метод
   - **Параметры запроса**: новые/удалённые query/path параметры, изменение обязательности
   - **Тело запроса**: новые/удалённые поля, изменение типов, изменение обязательности
   - **Тело ответа**: новые/удалённые поля, изменение типов, изменение структуры (вложенность)
   - **Статус-коды**: новые/удалённые коды ответа
   - **Заголовки**: изменения в required headers (особенно авторизация)

3. Классифицируй каждое изменение:
   - 🔴 **Breaking change** — удалён эндпоинт/поле, поле стало обязательным, изменился тип, изменился путь
   - 🟡 **Требует внимания** — новое необязательное поле, новый статус-код, новый эндпоинт
   - 🟢 **Безопасное изменение** — расширение документации, новое необязательное поле с дефолтом

4. Формат вывода — таблица или сгруппированный список по категориям (Breaking / Требует внимания / Безопасное), не сплошной текст.

5. В конце — краткий вывод: сколько breaking changes, какие тесты/коллекции точно надо обновить.

## Формат вывода (пример)

### 🔴 Breaking changes
| Эндпоинт | Изменение |
|---|---|
| POST /users | Поле `phone` стало обязательным |
| GET /orders/{id} | Удалён эндпоинт, заменён на GET /orders/v2/{id} |

### 🟡 Требует внимания
| Эндпоинт | Изменение |
|---|---|
| GET /users | Добавлен новый статус-код 429 (rate limit) |

### 🟢 Безопасные изменения
| Эндпоинт | Изменение |
|---|---|
| POST /users | Добавлено необязательное поле `middleName` |

**Итого:** 2 breaking changes — затронуты коллекции X, Y. Рекомендуется обновить тесты для POST /users и проверить, используется ли где-то старый GET /orders/{id}.

## Что НЕ делать

- Не делай вывод о breaking change, если не уверен(а) — лучше пометить как "требует проверки вручную".
- Не сравнивай версии без явного указания, какая из двух — старая, а какая новая (порядок важен для формулировок "добавлено"/"удалено").
- Не переписывай всю спеку целиком — только различия.
